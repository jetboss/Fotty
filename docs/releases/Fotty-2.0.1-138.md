## Production changes

Native playback keeps actual bounded NSError domain/code/depth/trigger evidence
for AVPlayerItem fatal status and failed-to-end notifications, rather than
replacing it with a literal unknown. A typed HTTP domain is required before a
numeric error-log code is reported as HTTP. The fatal item error outranks older
error-log entries. Exact source/request/item ownership and proxy-connection
fences prevent delayed deadlines or replaced attempts from creating false
failures. Both single-player and Watch Two retain their existing native owners.

Pre-item preparation adds separate finite stage/reason/domain/code/underlying
and HTTP-status fields. Original recovery errors remain private for unchanged
retry behavior; descriptions, URLs, headers and NSError userInfo do not enter
the bounded quality ring. Proxy health/cancellation does not invent a synthetic
AVFoundation cause. Preparation diagnostics merge only into the exact current
attempt. These classifications are evidence, not a proven explanation for every
CS upstream failure.

Watch Two shares the existing one-focused-pane audio policy and muted physical
test mode. Its item-status observation, readiness deadline and typed relay
diagnostics retain independent source, audio-focus and lifecycle ownership.
Public CS request-header admission remains build137's reviewed bounded contract;
no credentials, header or provider-label expansion. The owner-approved8443
exception is a runtime-only, exact-origin permission minted from the reviewed
DaddyLive/native manifest contract and bound to the exact delivery URL and
headers. It is not Codable; saved or injected session JSON cannot restore it.
Default443 admission, public/mixed-DNS rejection, redirect budgets, TLS and
credential restrictions remain unchanged. Both native owners receive their own
selected source's profile; Web handoff receives none. DNS validation remains a
preflight, not address-pinned egress.

The separate observation-only watchdog is published and activated. Exact
protected/cloud/GitHub receipts, bounds and exclusions are in
[the service record](../operations/Fotty-Watchdog-Service.md). It observes
admitted source metadata, accepted fixture integrity and monitor liveness; it
does not decode streams or execute repairs.

results, screenshots and the private preference copy. Builds are sequential;
no simulator or old installed Mac app is used. Temporary output and the owned UI
runner are removed after summarizing evidence; small source recovery receipts
are retained deliberately. The task-bound keep-awake process ends on completion.
