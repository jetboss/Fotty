## Recommended transfers, in order

1. **Cricket-aware match context.** Show confirmed score/innings/overs and actual
   session state in one compact place. Keep it useful when a feed is unavailable.
   First establish a reviewed, affordable data source and freshness contract; do
   not manufacture numbers from kickoff or a generic channel. This is the clearest
   Jio-specific product lesson for Fotty's cricket audience.
2. **Practical quality selection.** Add a comprehensible Auto/Data Saver/Best
   control only for supported variants or qualified alternative deliveries. Keep
   its selected value truthful and preserve the playback owner's controls. Do not
   promise an adaptive ladder for a fixed-quality feed.
3. **Clear audio/source meaning.** Expose a known commentary language and actual
   quality where the descriptor provides them, alongside the existing source
   selection. Persist a preference only when the selected source contract allows
   it; do not silently substitute a different programme or unknown-language feed.
4. **Useful discovery, modest scope.** Use existing interests/follows and relevant
   suggestions to lead to the next useful event. Preserve access to non-cricket
   sports; a fan should not need to search through a general entertainment wall.
   Jio's large content breadth and personalization machinery are not requirements
   for Fotty.

## Do not copy

- Entertainment tabs, micro-shows, engagement games/rewards or unrelated promotional
  furniture. They would compete with Fotty's watching task.
- Multi-camera/multi-stream work, which the owner explicitly excluded.
- Vertical cropping, 4K badges, language/CC promises or AI highlights without the
  actual supplied media/data and rights/capabilities. These are production inputs,
  not effects a client can honestly synthesize from a generic live stream.
- Claims that a large operator never buffers or that its adaptive implementation
  can be transplanted from a marketing description. Actual performance here is unknown.
