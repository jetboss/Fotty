### Confirmed complete-manifest repair

The first physical CNC attempt reached the real adapter and relay but failed because a two-byte playlist probe was forwarded upstream as a byte-range request. The origin returned HTTP 206 with two bytes and `Content-Range: bytes 0-1/721`; a whole-playlist request returned HTTP 200 with 721 bytes. Rewriting the partial representation could not produce a valid full playlist.

The focused repair suppresses Range and representation/cache preconditions only for known `.m3u8` targets. Detected playlists must be full HTTP 200 without Content-Range before rewriting or HEAD handling. Rewritten GETs return their own complete byte length without upstream validators; playlist HEAD omits upstream representation length/validators. Segment byte ranges remain intact. Partial or conditional MIME-only playlist responses fail closed, without hidden retries or broader source trust.
